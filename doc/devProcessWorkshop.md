## Repository Architecture

We will be following Unity's [best practices for organizing your project](https://unity.com/how-to/organizing-your-project).  

## Branching/Workflow Model

For branch control, we will use a slightly simplified gitflow. We will have two consistent branches, main and integration. From integration we will branch our feature branches, and merge back into integration once the feature is completed. This will keep the main branch clean as possible, and avoid creating conflicting code on our main. Integration will therefore be messier, but consistently contain the most advanced version of our project. 
Feature branches will be named <developer inital>f_<featureName> (EX: gf_packaging, jf_menus, df_backups). 


## Code Development & Review Policy


We will be following a scrum model for development.
